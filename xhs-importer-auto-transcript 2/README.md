# xhs-importer 自动视频文稿

这是 [Xiaohongshu Importer Plus](https://github.com/lxl448080113/ob-Plugin) 的本地扩展版，面向 **Apple Silicon Mac 上的桌面版 Obsidian**。小红书图文照常导入；视频会自动生成文稿并写回**同一篇笔记**。转录不需要 Codex；另有 Codex Skill 为图文和已完成文稿的视频生成「总结」「知识提炼」。

## 一条链接会怎样处理

**视频：** 小红书链接 → 插件在你设置的笔记文件夹创建 Markdown 笔记，不插入或下载视频封面 → 尝试读取小红书平台字幕 → 字幕不存在或不可用时，临时下载视频并在本机语音识别 → 将文字写入原笔记的 `## 视频文稿` → 清理临时视频 → 调用 Codex Skill 写入「总结」「知识提炼」。

**图文：** 小红书链接 → 插件按原设置保存正文和图片 → 调用 Codex Skill 写入「总结」「知识提炼」。图文不会启动转录程序。

视频文稿失败后会在 Obsidian 保持运行时自动重试，间隔依次为 1、5、15、30、60 分钟；仍失败时可在命令面板运行「重试当前小红书视频文稿」。自动重试队列保存在插件设置中，重启 Obsidian 后仍会继续。AI 处理需要 Codex 命令和网络；若失败，原笔记仍保留，可运行「生成或更新当前小红书笔记的总结和知识提炼」。

新导入的图文和视频笔记都会在属性中显示 `整理状态: 待整理`。AI 总结与视频转录不会修改它；只有你把来源内容整理进自己的知识笔记后，才手动改成 `已完成`。这项属性用于区分来源素材与个人整理，旧笔记不会被插件批量改动。

视频和图文都不再附加原帖的那段 `#话题#` 标签代码块。导入时还会去掉原帖标题末尾独立的 `#话题`，用于笔记文件名和标题属性；标题正文中的 `#` 会保留。插件设置里的笔记文件夹、图片文件夹、图片下载开关和 Frontmatter 字段由原有 `data.json` 控制，本扩展版不替你改这些设置。

## 生成后的笔记

视频笔记保留原帖链接、`[Video Link]` 和正文，不显示或下载视频封面，文件名也不添加 `[V]` 前缀，并新增一个 `## 视频文稿` 区域。文稿下方的“来源”会写明是“小红书平台字幕”还是“本地语音转录”。图文笔记的图片导入规则不变。

视频笔记里还有一段以 `<!-- xhs-transcript-data` 开头的 HTML 注释。它存放原帖、视频和字幕地址，供自动处理读取；在 Obsidian 编辑模式里可能看见，在阅读模式里通常隐藏。地址中的签名会过期，**不要把个人笔记连同这段注释上传到公开仓库**。本仓库只包含插件程序，不包含任何笔记或媒体地址。

## 文件包里有什么

| 文件 | 作用 |
| --- | --- |
| `main.js` | Obsidian 插件主程序；导入笔记、识别视频、启动自动转录并把结果写回原笔记 |
| `transcribe_note.py` | 依次尝试平台字幕和本机语音识别；无字幕时管理临时视频 |
| `skills/xhs-note-insights/SKILL.md` | Codex 生成一两句话的总结、详细的观点和操作方法 |
| `manifest.json` | Obsidian 识别插件所需的名称、ID 和版本信息 |
| `styles.css` | 原插件导入窗口的样式 |
| `setup.sh` | 创建本机 Python 环境、安装转录依赖和 Codex Skill |
| `requirements.txt` | `mlx-whisper` 和 `imageio-ffmpeg` 的固定版本 |
| `.gitignore` | 避免误上传个人设置、媒体和本机环境 |
| `LICENSE` | 原插件的 MIT 授权声明 |
| `README.md` | 本说明 |

**没有打包** `data.json`、Obsidian 笔记、图片、视频、Python 环境或语音模型。原因是前两项属于个人数据，后几项体积较大或可以按需重新安装。

## 安装：已经在用 xhs-importer

1. 下载本仓库文件并解压，确认文件夹内能看到 `main.js`、`transcribe_note.py`、`setup.sh`。电脑需安装 Python 3，安装依赖和首次下载模型时需要联网。
2. 在终端进入解压后的文件夹，运行 `bash setup.sh`，等待显示“本地转录环境已安装”。它把环境安装到 `~/Library/Application Support/xhs-importer-transcript/.venv`，并把 Skill 安装到 `~/.codex/skills/xhs-note-insights/`。首次语音识别还会下载约 1 GB 的模型文件。
3. 在你的 Obsidian 库中找到 `.obsidian/plugins/xhs-importer/`。先备份原 `main.js`，再将本仓库的 `main.js`、`manifest.json`、`styles.css`、`transcribe_note.py` 复制进去；**保留已有的 `data.json`**。
4. 重启 Obsidian，在“第三方插件”中确认 `Xiaohongshu Importer Plus` 已启用。

如果是新安装，先在 Obsidian 库的 `.obsidian/plugins/` 下创建 `xhs-importer` 文件夹，再按上面的步骤复制四个插件文件。新安装的默认保存位置可在插件设置中调整。

## 平时怎么用

1. 复制小红书笔记的分享链接或分享文本。
2. 在 Obsidian 按 `⌘P` 打开命令面板，运行 `Import Xiaohongshu note`；也可以点插件的侧边栏图标。粘贴链接，按原习惯选择是否下载图片，然后点击 `Import`。
3. 图文笔记会按原设置导入。视频笔记先创建，插件会提示“正在生成文稿”；处理完成后，同一篇笔记出现 `## 视频文稿`，并提示采用了字幕还是本机识别。随后插件会写入 `# 一、总结` 和 `# 二、知识提炼`，观点小节按 `## 1.`、`## 2.` 编号，更细的下级标题按 `### 1.1` 编号。Obsidian 显示文件名作为笔记标题，正文不重复写标题。重复运行只更新 AI 区块。

新导入的笔记自动处理。旧笔记不会被批量修改；打开旧笔记后，可用上述两个命令分别补写文稿和 AI 内容。

## 视频、模型与隐私

平台字幕和视频只从小红书域名读取。无字幕时，视频进入系统临时目录，由本机的 `mlx-whisper` 识别；正常完成或出现可处理的错误时，临时目录会连同视频删除，视频不会保存到 Obsidian 库。强制结束 Obsidian 或系统崩溃时，临时文件可能来不及清理。

语音识别在本机进行，不会把视频上传到第三方转录服务。首次使用需要下载模型，模型会缓存在电脑上，**不会随临时视频一起删除**。本机识别可能听错专有名词，重要内容请核对。

## 没有生成文稿时

| 看到的情况 | 怎么处理 |
| --- | --- |
| 提示缺少转录环境或依赖 | 在本仓库文件夹重新运行 `bash setup.sh`；确认 `transcribe_note.py` 已复制到插件文件夹 |
| 提示字幕或视频不可用 | 小红书签名链接可能已过期；重新导入原帖链接，或检查该视频是否仍可访问 |
| 笔记已创建，但一直没有 `## 视频文稿` | 等待视频下载和识别完成；若最终出现失败提示，按提示检查原因 |
| AI 总结失败或网络暂时不可用 | 原笔记和文稿保留；网络恢复后打开笔记，运行「生成或更新当前小红书笔记的总结和知识提炼」 |
| 更新原插件后自动转录消失 | 原插件更新可能覆盖 `main.js`；从本仓库重新复制四个插件文件，并保留 `data.json` |

转录失败不会删除已经创建的原笔记。插件只把文稿写入 `xhs-importer` 当前设置的默认笔记文件夹中的那篇视频笔记。

## 上传 GitHub 保存与以后恢复

新建仓库后，把**本文件夹内的源文件**上传到仓库根目录，GitHub 就会在仓库首页显示 `README.md`。不要上传 Obsidian 库中的 `data.json`、个人笔记、下载的图片和视频、`.venv` 或模型缓存；`.gitignore` 已列出常见的本地文件，但上传前仍应检查文件清单。

换电脑恢复时，从仓库下载这些文件，在新的 Apple Silicon Mac 上运行一次 `bash setup.sh`，再把四个插件文件复制到新 Obsidian 库的 `.obsidian/plugins/xhs-importer/`，重启 Obsidian。恢复个人保存位置和 Frontmatter 时，使用你自己备份的 `data.json`；本仓库不会替你保存它。
